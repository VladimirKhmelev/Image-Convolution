# Image Convolution — Документация

Учебный проект по параллельной обработке изображений. Реализует свёртку (convolution) изображений с различными фильтрами, демонстрируя разные стратегии распараллеливания задачи.

---

## Возможности

- **24 фильтра** четырёх размеров (3×3 … 9×9): каждый размер реализует одинаковый набор типов — Идентити, Box Blur, Gaussian Blur, Резкость, Края, Эмбосс
- **4 стратегии параллелизации**: по пикселям, по строкам, по столбцам, по сетке (2D grid с настраиваемой формой)
- **Цепочки фильтров**: последовательное применение нескольких фильтров; опциональная математическая композиция в одно ядро
- **Кэш-friendly тайлинг**: флаг `--tile-size` задаёт размер тайла в пикселях для подбора размера сетки под L1/L2 кэш
- **GUI-режим**: интерактивный интерфейс на Compose Desktop
- **CLI apply-режим**: применить фильтр(ы) и сохранить результат — быстро, один проход
- **CLI benchmark-режим**: полный бенчмарк всех стратегий с прогревом JIT и подробной статистикой

## Запуск

### GUI (по умолчанию)

```bash
./gradlew run
```

Интерфейс разделён на два блока:

**Сайдбар (левая панель)** — все настройки:
- **Цепочка фильтров** — список фильтров, применяемых по порядку. Кнопка «+ Добавить фильтр» добавляет ещё один шаг. Каждый шаг можно удалить кнопкой «×».
- **Объединить в одно ядро** — чекбокс появляется при двух и более фильтрах. Показывает итоговый размер составного ядра (например, `5×5` для двух `3×3`).
- **Алгоритм** — выбор стратегии распараллеливания.
- **Потоки** — слайдер 1 до числа ядер (виден для параллельных режимов).
- **Строк/Столбцов сетки** — два слайдера 1–16 (видны только при «По сетке»).
- **Кнопка «Применить»**, время последнего запуска, сообщения об ошибках.

**Область изображений (правая часть)** — два панели рядом: оригинал и результат. Кнопки «Загрузить» и «Сохранить» находятся под соответствующей панелью.

### CLI — apply (быстрый запуск)

Применяет фильтр(ы) одним проходом и опционально сохраняет результат на диск.

```bash
./gradlew run --args='<путь> <фильтр...> [--strategy <стратегия>] [--output <файл>] [--threads N] [--compose] [--tile-size N] [--grid-rows R] [--grid-cols C]'
```

Пример вывода:
```
Изображение : photo.png (1920×1080)
Стратегия   : По строкам, 8 потоков
Фильтры     : Gaussian Blur
Время       : 91 мс
Сохранено   : result.png
```

## Флаги CLI

### Общие (работают в обоих режимах)

| Флаг            | Описание                                                                 | Пример                       |
|-----------------|--------------------------------------------------------------------------|------------------------------|
| `<image>`       | Путь к изображению (обязательный)                                        | `photo.png`                  |
| `[фильтр ...]`  | Один или несколько фильтров — образуют цепочку (pipeline)                | `"Gaussian Blur" "Резкость"` |
| `--threads N`   | Максимальное число потоков                                               | `--threads 4`                |
| `--compose`     | Скомпоновать фильтры цепочки в одно ядро                                 | `--compose`                  |
| `--tile-size N` | Размер тайла в пикселях для BY_GRID (вместо `--grid-rows`/`--grid-cols`) | `--tile-size 64`             |
| `--grid-rows R` | Явное число строк сетки (игнорируется при `--tile-size`)                 | `--grid-rows 2`              |
| `--grid-cols C` | Явное число столбцов сетки                                               | `--grid-cols 8`              |

### Только apply-режим

| Флаг              | Описание                                                                 | Пример                |
|-------------------|--------------------------------------------------------------------------|-----------------------|
| `--strategy <s>`  | Стратегия: `seq`, `pixels`, `rows`, `cols`, `grid` (по умолчанию: `seq`) | `--strategy rows`     |
| `--output <файл>` | Путь для сохранения результата (png); без флага результат не сохраняется | `--output result.png` |

### Только benchmark-режим

| Флаг                   | Описание                                                                                              |
|------------------------|-------------------------------------------------------------------------------------------------------|
| `--benchmark`          | Включает benchmark-режим: прогрев JIT + 30 замеров всех стратегий, подробная таблица                  |
| `--kernel-size N[,N…]` | Ограничить бенчмарк фильтрами указанных размеров (3, 5, 7, 9). Ускоряет прогон при тестировании части матриц | 

Все числовые флаги принимают форму `--flag N` и `--flag=N`.

Если `--threads` не указан — используются все доступные процессоры.

## Примеры

### Apply-режим

```bash
# Применить Gaussian Blur последовательно, сохранить результат
./gradlew run --args='photo.png "Gaussian Blur" --output result.png'

# Применить параллельно по строкам, 4 потока
./gradlew run --args='photo.png "Gaussian Blur" --strategy rows --threads 4 --output result.png'

# Цепочка фильтров: размыть → заострить, сохранить
./gradlew run --args='photo.png "Gaussian Blur" "Резкость" --strategy rows --output result.png'

# То же, но скомпоновать в одно ядро
./gradlew run --args='photo.png "Gaussian Blur" "Резкость" --compose --strategy rows --output result.png'

# По сетке с тайлом под L1-кэш (~32 KB)
./gradlew run --args='photo.png "Gaussian Blur" --strategy grid --tile-size 90 --output result.png'

# Конкретная форма сетки: 2 строки × 8 столбцов
./gradlew run --args='photo.png "Края" --strategy grid --grid-rows 2 --grid-cols 8 --output result.png'
```

### Benchmark-режим

```bash
# Бенчмарк всех фильтров, все доступные потоки
./gradlew run --args='photo.png --benchmark'

# Только 3×3 фильтры — в ~4 раза быстрее полного прогона
./gradlew run --args='photo.png --benchmark --kernel-size 3'

# Несколько размеров
./gradlew run --args='photo.png --benchmark --kernel-size 3,5'

# Только Gaussian Blur 3×3, не более 4 потоков
./gradlew run --args='photo.png "Gaussian Blur 3×3" --benchmark --threads 4'

# Цепочка + сравнение с составным ядром
./gradlew run --args='photo.png "Gaussian Blur" "Резкость" --benchmark --compose'

# Сетка с тайлом под L1: для 1920×1080 при tileSize=90 → 12×22
./gradlew run --args='photo.png --benchmark --tile-size 90'

# Конкретная форма сетки
./gradlew run --args='photo.png --benchmark --threads 8 --grid-rows 2 --grid-cols 8'
```

> **Важно:** все аргументы программы передаются как одна строка в `--args='...'`.
> Не разделяйте их — gradle примет остальное за свои собственные задачи.

## Фильтры

Граничные пиксели обрабатываются с zero-padding (выход за границу считается нулём).

Каждый размер реализует одинаковый набор типов фильтров — удобно сравнивать визуальный эффект и производительность при росте ядра.

| Тип фильтра       | 3×3 | 5×5 | 7×7 | 9×9 | Примечание                                                                                |
|-------------------|:---:|:---:|:---:|:---:|-------------------------------------------------------------------------------------------|
| **Идентити**      |  ✓  |  ✓  |  ✓  |  ✓  | Не изменяет изображение; все варианты дают одинаковый результат (zero-padding invariance) |
| **Box Blur**      |  ✓  |  ✓  |  ✓  |  ✓  | Все веса = `1/N²`; при большем ядре размытие заметно сильнее                              |
| **Gaussian Blur** |  ✓  |  ✓  |  ✓  |  ✓  | σ = 0.85 / 1.0 / 1.5 / 2.0; нормированная сумма = 1                                       |
| **Резкость**      |  ✓  |  ✓  |  ✓  |  ✓  | Ромбовидная «корона» отрицательных весов; центр компенсирует, сумма = 1                   |
| **Края**          |  ✓  |  ✓  |  ✓  |  ✓  | Лапласиан; центр = N²−1, остальные = −1, сумма = 0                                        |
| **Эмбосс**        |  ✓  |  ✓  |  ✓  |  ✓  | Диагональный градиент; сумма = 1                                                          |

### Производительность по размеру

| Ядро | Операций/пиксель | ×3×3 |
|------|------------------|------|
| 3×3  | 9                | 1×   |
| 5×5  | 25               | ~3×  |
| 7×7  | 49               | ~5×  |
| 9×9  | 81               | ~9×  |

## Стратегии параллелизации

| Стратегия            | CLI-ключ | Описание                                                                                                                                                                                                                                                                                                                             |
|----------------------|----------|--------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| **Последовательный** | `seq`    | Один поток, строка за строкой                                                                                                                                                                                                                                                                                                        |
| **По пикселям**      | `pixels` | Все пиксели делятся на N чанков, каждый поток обрабатывает свой чанк                                                                                                                                                                                                                                                                 |
| **По строкам**       | `rows`   | Строки изображения делятся между потоками                                                                                                                                                                                                                                                                                            |
| **По столбцам**      | `cols`   | Столбцы изображения делятся между потоками                                                                                                                                                                                                                                                                                           |
| **По сетке**         | `grid`   | 2D-разбиение на `R × C` ячеек. В `apply`-режиме без явных `--grid-rows`/`--grid-cols` форма авто: `√T × ⌈T/√T⌉` (близко к квадрату). В `benchmark`-режиме дополнительно тестируются полосы `1×T` и `T×1` для наглядного сравнения кэш-эффектов. Горизонтальные полосы дружелюбнее к строчному размещению данных, вертикальные — нет. |

## Архитектура проекта

### Data flow

```
Файл на диске
    │
    ▼
BufferedImage  ──toGrayImage()──▶  GrayImage(width, height, FloatArray)
                                        │
                                        │  для каждого фильтра в pipeline:
                                        │  applyKernelAt(x, y, kernel) → Float
                                        │  (zero-padding на границах)
                                        ▼
                                   GrayImage (результат)
                                        │
                                        │  clamp [0, 255] → Int
                                        ▼
                                   BufferedImage  ──▶  PNG на диск / GUI
```

**Два режима применения фильтров:**
- **Pipeline** — фильтры применяются последовательно: выход предыдущего становится входом следующего.
- **Compose** (`--compose`) — фильтры математически сворачиваются в одно ядро (`composeKernels`), затем применяется единственный проход. Результат тот же, количество проходов по изображению — одно.

### Структура файлов

```
src/main/kotlin/
├── Main.kt              — точка входа, разбор аргументов CLI
├── Benchmark.kt         — runApply (быстрый запуск) и runBenchmark (полная статистика)
├── convolution/
│   ├── Convolution.kt   — алгоритмы свёртки (sequential + parallel)
│   ├── Kernels.kt       — реестр всех фильтров (Kernels.all), агрегирует размеры
│   └── kernels/
│       ├── Kernels3x3.kt — 6 фильтров ×  9 оп/пиксель
│       ├── Kernels5x5.kt — 6 фильтров × 25 оп/пиксель
│       ├── Kernels7x7.kt — 6 фильтров × 49 оп/пиксель
│       └── Kernels9x9.kt — 6 фильтров × 81 оп/пиксель
└── ui/
    └── App.kt           — Compose Desktop GUI
```

## Известные особенности

> **Гибридные CPU (Intel 12th gen+, некоторые ARM):** на процессорах с P-ядрами (производительными) и E-ядрами (эффективными) планировщик ОС сам решает, на каких ядрах запускать потоки. При `--threads N` нет гарантии, что задействуются именно P-ядра — часть потоков может попасть на E-ядра и замедлить результат. Это объясняет повышенный CV% в отдельных запусках бенчмарка.

## Тесты

```bash
./gradlew test
```

После запуска доступны два HTML-отчёта:

| Отчёт             | Путь                                        |
|-------------------|---------------------------------------------|
| Результаты тестов | `build/reports/tests/test/index.html`       |
| Покрытие (JaCoCo) | `build/reports/jacoco/test/html/index.html` |

Тесты охватывают модуль `convolution` (задачи 1 и 2) и проверяют свойства из схемы тестирования задания:

**`SequentialConvolutionTest`** — 15 тестов:
- Фильтр-идентити возвращает то же изображение (разные размеры: 1×1, 1×N, N×1, N×M)
- Нулевое ядро → полностью чёрное изображение
- **Свойство композициональности**: последовательное применение k₁ → k₂ совпадает с применением `compose(k₁, k₂)` — проверяется на внутренних пикселях (граничные пиксели исключаются, так как zero-padding даёт расхождение именно там)
- **Zero-expansion invariance**: обрамление ядра нулями не меняет результат
- Крайние случаи: 1×1 изображение, одна строка, один столбец, изображение равно размеру ядра

**`ParallelConvolutionTest`** — 11 тестов:
- Все 4 параллельных режима дают тот же результат, что и sequential (проверяется на 1/2/4/8 потоках)
- Все 6 ядер × все 4 режима параллелизации
- Явные формы сетки `BY_GRID` включая сетку крупнее изображения
- Больше потоков чем строк/столбцов в изображении
- Случайные ядра размерами 1×1…7×7
- Параллельный pipeline совпадает с последовательным
